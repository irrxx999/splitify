# Splitify

Telegram-бот для подсчёта долгов в путешествии. Java 17, Maven, telegrambots (long polling), SQLite.
Пользователи пишут по-русски, весь текст бота и комментарии в коде — на русском.

## Сборка и запуск (Windows, PowerShell)

- Собрать: `.\scripts\build.ps1` (clean package → `target\splitify.jar`)
- Только проверить компиляцию: `.\scripts\build.ps1 -Compile` — безопасно, когда бот запущен
- Запустить:
  ```powershell
  $env:BOT_TOKEN = "..."            # обязателен
  $env:PROXY = "http://127.0.0.1:10809"   # необязателен; http://... или socks5://...
  java -jar target\splitify.jar
  ```
- Пока бот запущен, он держит `target\splitify.jar` — `clean package` упадёт. Сначала остановить бота (Ctrl+C).
- Maven в PATH может не быть: скрипт ищет его сам, в том числе в IntelliJ IDEA.
- Тесты (JUnit 5): `.\scripts\build.ps1 -Test` — безопасно, когда бот запущен. Лежат в `src/test/java/splitify`:
  `SettlementServiceTest` (расчёт долгов, замороженный курс, свойство «баланс сходится в ноль») и `CurrencyTest`.
  Менял расчёт или валюты — добавь тест и прогони все перед коммитом. `Db` и `SplitifyBot` тестами пока не покрыты.

## Устройство

- `Main` — читает `BOT_TOKEN` и `PROXY`, открывает БД, регистрирует бота.
- `SplitifyBot` — разбор команд, ответы, диалог `/spend` на inline-кнопках.
- `SettlementService` — расчёт: траты → базовая валюта → балансы → минимум переводов → валюта получателя.
- `Db` — SQLite (`splitify.db` рядом с jar). Все методы `synchronized`, суммы хранятся как TEXT ради точности BigDecimal.
- `Currency` — enum валют с алиасами (`RUB`, `рубли`, `₽`).

## Правила

- **Валюты** всегда приводить через `Currency.parse(...)`, в БД и сравнениях использовать `.name()` (`"RUB"`). Не сравнивать сырые строки от пользователя.
- **Деньги** — только `BigDecimal`, никаких `double`.
- **Курс замораживается** в момент `/spend` (`rate_at_time`); итог фиксируется при `/close` в таблице `settlements`. Не ломать эти гарантии.
- **Состояние привязано к чату** (одна активная поездка на `chat_id`), а не к теме группы и не к пользователю.
- **Темы групп:** ответы отправлять с `messageThreadId` исходного сообщения (см. `send(...)`), иначе уйдут в General.
- **Диалог `/spend`:** черновики в памяти, ключ — чат+пользователь; callback-данные начинаются с `sp:` и должны умещаться в 64 байта. Нажимать может только тот, кто начал.
- **Голос бота:** женский род («Записала», «Зафиксировала»), эмодзи в ответах, ошибки — коротко и понятно, с подсказкой формата.
- Изменения в схеме БД — только мягкими миграциями в `Db.migrate()`: база у пользователя уже живая.

## Безопасность

- Токен бота — как пароль: не печатать, не логировать, не коммитить, не вставлять в чат. Только переменная окружения.
- `splitify.db` содержит данные людей — не читать без необходимости и не коммитить (уже в `.gitignore`).
- Перед коммитом проверять `git status`: в индексе не должно быть `*.db`, `.env`, `target/`.
